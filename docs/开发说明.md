# 开发说明

面向要改这个插件的人。先用 README 把插件跑起来，再看这份。

---

## 一、整体结构

插件是**一个 Lua 文件**，但里面塞了四段 Python：

```
src\zhouxiao.lua   ← Aegisub 加载的就是这个文件，4846 行
    │
    ├─ 前面 ~990 行：Lua 部分（菜单、导入、配对、同步时间、歌词定位、工作台调度）
    │
    └─ 文件末尾 5 段长字符串（[==[ ... ]==] 包着）：
         AUTOTIME_PY   自动粗轴（人声分离 + whisper 强制对齐）
         FXEDIT_PY     特效工作台窗口（tkinter，三页）
         ZXCORE_PY     工作台底层（ASS 读写、VSFilter 渲染、K 帧时间轴、模板引擎）
         ZXAI_PY       AI 助手协议层（OpenAI 兼容 / Anthropic）
         INSTALL_PS1   组件安装脚本
```

Aegisub 每次跑宏时，Lua 把这些字符串**原样写到组件目录**再启动：

```
Aegisub目录\zhouxiao-autotime\
    autotime.py  fxedit.py  zxcore.py  zxai.py  install.ps1   ← 每次覆盖（BOM 由 Lua 加）
    env\       独立 Python 环境（uv 装的，不碰系统 Python）
    models\    UVR-MDX-NET-Voc_FT.onnx + whisper base.pt
    kara_pack\ 按需下载的社区卡拉OK模板
    ai.json / fx_presets.json / lead.txt / fx_dump.tsv ...    ← 用户数据
```

**所以：改组件目录里的 Python 是白改，下次跑宏就被覆盖。** 只改 `src\`。

### 为什么这么设计

- 单文件 = 用户「下载一个文件扔进 autoload」就能用，不用装依赖；
- 组件重（torch + 两个模型约 1.2GB），所以按需下载、放在可整个删除的目录里；
- Python 部分要 tkinter / lupa / PyAV，Lua 干不了，所以分成外部窗口。

## 二、改代码的流程

```bat
:: 1. 改 src\ 里的文件（Lua 那部分改 src\zhouxiao.lua，Python 四段改各自的 .py）
:: 2. 塞回 lua（src\zhouxiao.lua 和 Aegisub 的 automation\autoload\zhouxiao.lua 一起写）
python tools\embed.py

:: 3. 确认三个地方一致
python tools\status.py

:: 4. 跑测试
python tools\selftest.py --all

:: 5. 回 Aegisub 点「重新扫描自动化目录」
```

**两份 lua 必须一模一样**（`selftest.py` 会逐字节比）：`src\zhouxiao.lua` 是权威版本
（Lua 那部分就在这里改），线上那份是它的部署。`embed.py` 以 `src\zhouxiao.lua` 为底、
把五段 Python 塞进去，**两份一起写**，所以改完容器也不用记着「再拷一份过去」——以前就漏过这一步，
线上插件比源码旧，测试和实际跑的不是一个版本。

改版本号：`python tools\embed.py --version 0.25`（lua 里的 `script_version` 和
`src\VERSION` 一起改）。发布时打 tag：`git tag v0.25 && git push --tags`。

`tools\extract.py` 是从 lua 反抽源码用的（比如接管一份别人的 lua），日常不用。

### 三个硬约束

1. **行尾必须 LF**。全仓库靠 `.gitattributes` 固定；`tools\embed.py --check` 会对比
   「src 塞回 lua 后是否逐字节等于原文件」，行尾一变这条就红。
2. **源码里不能出现 `]==]`**。内嵌块用 `[==[ ... ]==]` 包着，正文里出现这个会提前截断。
   `embed.py` 会拦下来。
3. **`autotime.py` / `install.ps1` 的源码不带 BOM**。BOM 是 Lua 写文件时加的
   （PowerShell 5 读中文需要）。`embed.py` 会拒绝带 BOM 的源文件。

## 三、Lua 部分怎么读

`zhouxiao.lua` 前半部分的重点：

| 位置 | 干什么 |
|---|---|
| `STYLES` / `KINDS` / `PAIR` / `SIDE` | 13 个标准样式，中日成对关系 |
| `sides(subs)` | 按文件顺序分出中日两组行号，第 N 个中文 ↔ 第 N 个日文 |
| `ensure_styles(subs)` | 缺什么样式补什么，返回「在前面插了几行」——**所有选中行下标都要先 shift 这个数** |
| `resolve_catalog` / `guess_catalog` / `guess_number` | 样式方案：文件头记着的 > alias 表 > 目录名；编号从文件名猜 |
| `spawn(cmdline, opts)` | FFI 调 `CreateProcessW` 启动外部程序（`CREATE_NO_WINDOW`，不闪黑窗） |
| `workbench(tab)` | 7/8/9 三个菜单共用：dump 整份字幕 → 起窗口 → 读回 ops → 应用 → 一步撤销 |
| `apply_ops(subs, path)` | ops 文件语义：`set` / `del` / `ins` / `style` / `info`，**按行号从大到小**执行 |

`set_kind` / `insert_after` 这类会改结构的操作，都先 `shift(sel, ensure_styles(subs))`。

### 工作台的数据流

```
Lua  dump_subs()  ──►  fx_dump.tsv      （每行：i, class, 各字段；\t 分隔，值做转义）
                       fxjob.json       （tab, dump, sel, active, video, time, vsfilter, out, catalog…）
                     起 fxedit.py --job fxjob.json
Python 用户在窗口里改  ──►  fx_ops.tsv   （set/del/ins/style/info）
Lua   apply_ops()  ──►  改 subs，然后 set_undo_point("轴效特效工作台")
```

**调试工作台**：`fxedit.py` 崩了会把 traceback 写进组件目录的 `fxedit.log`；
`fx_job.json` 留着上一次的输入，可以手动
`python fxedit.py --job fxjob.json` 复现（不用开 Aegisub）。

## 四、Python 部分

- **`zxcore.py`**（无界面，被另外两个用）
  - `Doc` / `Edits`：读 fx_dump.tsv、攒改动
  - `parse_ass` / `template_rows`：读 .ass，挑出模板行
  - `auto_k` / `k_starts` / `syllables`：`\k` 的写回与读回，**两者必须往返一致**
  - `Kara`：在 Python 里用 lupa 跑 Aegisub 自带的 `kara-templater.lua`
  - 渲染：ctypes 调 Aegisub 自带的 xy-VSFilter（CSRI），PyAV 取帧和音频
- **`fxedit.py`**：`Player`（预览播放器）/ `FxTab` / `KTimeline` / `KaraTab` / `AiTab` / `App`
- **`zxai.py`**：两种协议的流式 + 工具调用，只用标准库 urllib
- **`autotime.py`**：UVR MDX-Net 人声分离（DirectML）→ whisper base 强制对齐（CPU）→
  修开头提前量、吸附、补句尾拖长音

### 字体文件夹（0.25）：不装进系统也能用

用户不想为了做特效把字体装进系统，所以走的是「只注册给本进程」：

- `AddFontResourceExW(路径, FR_PRIVATE=0x10, NULL)`：进程内注册，**不写注册表、
  不往系统字体目录拷东西，进程退出就没了**。所以 Aegisub 关掉后再开要重新注册。
- 两条路都做同一件事：
  - **Aegisub 进程**（`zhouxiao.lua`）：插件加载时、进工作台前、出工作台后各读一次
    组件目录的 `fx_settings.json` 里的 `fonts_dir`，然后注册。目录用 FFI 的
    `FindFirstFileW/FindNextFileW` 走（宽字符路径，中文文件名没问题，不依赖 lfs）。
  - **工作台进程**（`zxcore.load_fonts`）：ctypes 调同一个 API。所以工作台里预览、
    量字宽也认这些字体。
- 家族名从字体文件的 `name` 表里读（`zxcore.family_names`）：中文名优先，其次英文的
  排版名（nameID 16），Mac 平台那份不要（解出来是乱码）。ttc/otc 里会装好几个字体，
  表偏移是**相对文件开头**的绝对偏移（不是相对子字体），写测试造 ttc 时踩过。
- 列进界面前先用 GDI 验一遍（`usable_fonts` → `resolve_face` 看 `GetTextFaceW` 拿到的名字
  是不是它自己）：名字不对的、字体文件坏的一律不列，免得用户选了发现没效果。
- 预览用的是 Aegisub 自带的 xy-VSFilter（GDI 找字体），所以**进程里注册过它就能渲染**，
  不需要装进系统。这条有测试兜着：同一份字幕、只换字体名，文件夹字体和「不存在的名字」
  （必然回退）渲出来的画面必须不一样。
- Aegisub 自己的预览有两条渲染器，**两条都认进程里注册的字体**：
  - **CSRI（xy-VSFilter）**：GDI 找字体，注册过就能渲染（`test_fonts.py` 里真渲染验过）。
  - **libass**（增强版 Aegisub 3.4.2 的默认选项 `Subtitle.Provider = "libass"`）：
    Windows 桌面版初始化时说得很直白——`Using font provider directwrite (with GDI)`。
    它枚举字体走的是 GDI（`ass_directwrite.c` 里 `EnumFontFamiliesW` +
    `IDWriteGdiInterop::CreateFontFaceFromHdc`），所以 `AddFontResourceEx(FR_PRIVATE)`
    注册的字体也看得见。**这条不是推的，是真机 A/B 验的**：
    `tests\test_aegisub_preview.py`（见「五、测试」）。
- 局限：只对本进程有效。给别人出片 / 上渲染服务器时字体得跟着走
  （Aegisub 的字体收集器），这条写在用户文档里了。

### 真 Aegisub 的预览：`tests\test_aegisub_preview.py`

字体注册是进程级的，在测试进程里怎么量都量不出「Aegisub 自己认不认」。所以这条测试**真开一次
Aegisub**：从本机那份 Aegisub 复制一份**隔离的**安装（不动你正在用的那个，两个进程互不影响），
往里放插件 + 一份指向 `ZX_FONT_DIR` 的 `fx_settings.json`，开两次做 A/B：

| 趟 | 设置 | 期望 |
|---|---|---|
| A | 字体文件夹在 | libass 日志里那两个字家族名都解析到**字体文件里那个名字** |
| B | 设置挪走（不注册）| 同样的名字和「绝无此字体XYZ」一个下场，都回退（ArialMT → MicrosoftYaHeiUI）|

判据是 **Aegisub 自己写的日志**（`log\<时间>.json` 里 `subtitle/provider/libass` 的
`fontselect:` 行）——纯文本、不靠肉眼；另外按窗口标题各截一张自己的窗口比像素，A/B 必须不一样。

```bat
<组件目录>\env\Scripts\python.exe tests\test_aegisub_preview.py --fresh
```

几条规矩，改这个测试时别丢：

- 测试台在 `%TEMP%\zx_aeg_preview\`，**必须纯 ASCII 路径**。插件里 `zx_home()` 有一条既有设计：
  `?user` 带非 ASCII 字符（比如 Aegisub 装在中文目录）时会退到 `%ProgramData%\zhouxiao-autotime`，
  把测试台放在本仓库路径下（`轴效插件\...` 含中文）就会去读那份设置，A 趟变成「什么都没注册」，
  看起来就像字体机制失效——我在这上面白绕了两圈。
- **Aegisub 开头的那些选项框会挡住渲染**：模态框在的时候主窗口是禁用状态，预览根本不画，
  日志里也就没有 `fontselect`。素材带上 `YCbCr Matrix: TV.709` + `LayoutResX/Y`（少弹框），
  脚本里再兜一层：把不属于主窗口、又属于 Aegisub 进程的可见顶层窗口按掉（回车 / `WM_COMMAND IDOK`）。
  点掉之前别急着重画窗口——重画一个被禁用的窗口是没用的。
- 会弹两个真 Aegisub 窗口、抢焦点，所以不进自动套件（`tests\run_all.py` 的 `SKIP`）。
- `zx_home()` 的中文回退是**设计**（系统用户名是中文时 `?user` 也是中文），不是 bug；
  但这条测试因此必须用 ASCII 路径。

### 搭测试台的两个现成东西

- `tools\testconfig.py`：路径 + `load_src()`（从 src 导入并把 HOME 指到组件目录）+
  `load_lua(src, spawn=)`。
- `tests\luaharness.py`（给 `selftest.py` 用）和 `tests\bootstrap.py` / `tests\fixtures.py`：
  假 Aegisub API、假 subs 表、合成字幕与导出文件。

### 踩过的坑（改测试时别再踩）

1. **假 `spawn` 必须在 `lua.execute` 之前设**。插件里 `spawn` 是整块 chunk 的局部量，
   加载时宏闭包已经绑死；加载完再设全局，跑测试会**真的弹 pythonw 窗口**。
   用 `testconfig.load_lua(src, spawn=...)`。
2. **lupa 的 LuaJIT 打不开含中文的路径**。测试用的临时文件放纯英文的 `%TEMP%` 下；
   个别测试（`test_show.py`，它要测中文的方案名）干脆把 Lua 的 `io.open` 换成用 Python 开文件。
3. **假 aegisub API 要按需补桩**。0.24 用到 `progress.task` / `text_extents` /
   `progress.is_cancelled` / `dialog.display` 的两个返回值，缺哪个哪条路径就炸。
4. **`ffi.string()` 只吃 `char *`**：传 `uint16_t[?]`（宽字符路径）会报
   "cannot convert 'unsigned short [?]' to 'const char *'"。要拿宽字符串当 key 就自己
   按字节拼（见 `zhouxiao.lua` 的 `wkey`）。
5. **`csri_render` 的时间是「秒」，不是毫秒**。传成毫秒（比如 1000）那一帧就没有任何
   字幕，画出来和背景一模一样，很容易误判成「字体没生效」。
6. **造 ttc 测试数据时表偏移要改成绝对偏移**（`make_ttc` 里那段循环）：按「子字体内部偏移」
   写出来的 ttc，解析器读不到名字表。

### 加一条测试的写法

照 `tests\test_kara_parity.py` 抄：

```python
import bootstrap              # 第一行，放好 sys.path
import testconfig as C
import fixtures as F

z, fe, ai = C.load_src()      # 从 src 导入，HOME 指向组件目录

OK, BAD = [], []
def check(name, cond, detail=""):
    (OK if cond else BAD).append(name)
    print(("  OK   " if cond else "  FAIL ") + name + (("   " + str(detail)) if detail and not cond else ""))

def main():
    ...
    print("\n通过 %d 项，失败 %d 项" % (len(OK), len(BAD)))
    return 1 if BAD else 0

if __name__ == "__main__":
    raise SystemExit(main())
```

新文件放 `tests\test_*.py` 就会被 `run_all.py` 自动收进套件。

**断言要能真的失败**：写完故意改坏插件里对应的那处（比如把编号专用的分支去掉），
确认测试变红——不变红说明写成了恒真式。几个关键测试都这么验过。

## 六、发布 / 分发

- 用户只需要 `zhouxiao.lua` 一个文件。组件按需下载，不进仓库。
- **不要提交**：`ai.json`（里面是用户自己的 Key）、任何 IP / 域名 / 端口 / 账号 /
  密钥、`kara_pack\`（社区模板，许可归各原作者）、`.venv` / 模型文件。

## 七、上手要准备什么

这份文档不写具体路径：clone 下来之后，「Aegisub 装在哪」「测试视频放哪」是你自己机器上的事，
每个人不一样。需要的东西是：

- **一份增强版 Aegisub**（`automation\autoload\` 里放 `zhouxiao.lua`）。
- **组件环境的 Python** 来跑测试。第一次让插件跑一次宏（或点「1 导入 txt + 自动粗轴」）
  它会把组件装到 Aegisub 的 `zhouxiao-autotime\` 里，之后用
  `<组件目录>\env\Scripts\python.exe` 跑测试即可。测试依赖 lupa / PyAV / torch / numpy，
  只装在组件环境里——用系统的 Python 跑会 ImportError。
- **测试素材自己造**：`tests\fixtures.py` 会现场合成字幕、导出文件，GUI 测试还会合一段
  测试视频，所以自动测试不依赖任何外部素材。要用手上的真实视频测，
  设环境变量 `ZX_VIDEO` 指过去（`tools\testconfig.py` 里还有 `ZX_COMPONENT` / `ZX_PY` /
  `ZX_AEGISUB` / `ZX_KARA_TEMPLATE`）。
- **改过 `zhouxiao.lua` 后**，回 Aegisub 点「重新扫描自动化目录」才生效。
